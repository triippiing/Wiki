01 What it is
01 Three skills, one idea: every frame is a function of time OVERVIEW ▶

Motion Kit is three Claude Code skills that turn a project's UI into motion, all in code. motion-design plans a promo and stops for approval. motion-video builds it as one HTML page whose seek(t) draws any frame from the time alone, then renders that page to MP4 with Playwright and ffmpeg, cut to a song's measured beat grid. motion-ui brings the same closed-form springs into a real product UI. There is no After Effects, Remotion or Lottie in the chain.

The look and the build rules adapt the open prompt template by zero (@twoclipping): one shape that never cuts, a cursor that drives every change, springs everywhere, and a last frame identical to the first so the clip loops.

Credits. Prompt template and direction: zero (@twoclipping). Transition catalog: Jakub Antalik, transitions.dev. Build workflow: Jesse Vincent, Superpowers. Demo music: "Tints" by Anderson .Paak featuring Kendrick Lamar, from Oxnard (2018), all rights with the artists. House font: Geist by Vercel. Tools: Playwright, FFmpeg, NumPy, Claude Code. Full list: CREDITS.md.

03 Install
03 Clone, install, check SETUP ▶
git clone https://github.com/triippiing/motion-kit.git ~/motion-kit ~/motion-kit/install.sh ~/.claude/skills/motion-video/scripts/doctor.sh # re-run any time something fails oddly

install.sh symlinks each folder in ~/motion-kit/skills/ into ~/.claude/skills/ (it refuses to replace a real folder of the same name), installs ffmpeg (Homebrew), numpy and Playwright with its Chromium when they are missing, then runs the doctor. The doctor lists anything still MISSING with the exact fix. Only Homebrew itself needs a manual install, because it asks for a password.

Prerequisites: Homebrew, Node 20 or newer and Python 3. Rendering fetches the house font from Google Fonts, so it needs a network connection. The scripts put /opt/homebrew/bin on their own PATH, so they work even when Claude's shell has not.

With Claude. Open Claude Code in the clone, or give it the repo URL. CLAUDE.md explains the whole project: pipeline, page contract, rules, code map and tests. A fresh Claude session with no other context used it to make a working video on the first try.

05 Pipeline
05 From a song to a rendered loop PIPELINE ▶

The order is fixed: song, then song.json, then the sync check by ear, then a state table, then the approval gate, then the seek(t) page, then beat stills, then the render. Nothing is coded until the table is approved.

  1. analyze_song.py measures BPM and the beat grid and writes song.json and clip.wav.
  2. sync.mjs: you check the grid by ear and mark moments (step 06).
  3. Claude writes one row per beat: something happens on every beat, and the last row returns to the first state.
  4. You approve or change the table.
  5. Claude edits only the tables in index.html: states(), cursor(), content, extraSfx().
  6. beat_stills.mjs writes one still per beat, a contact sheet and a loop-seam check. Read the sheet before rendering.
  7. render.mjs renders 60 fps, 4 subframes per frame, to out/video.mp4.

Everything above rests on one idea: a value that changes target many times is still a pure function of time. This is the heart of shared/springs.js (source, lines 46 to 63 at 8247624):

// A value that retargets many times, as a pure function of t: `from` plus one // spring per change, each animating only that change's delta. A spring that // starts at its change time adds zero displacement and zero velocity at that // instant, so the sum is continuous in both -- no state between frames. function track(t, o) { const changes = o.changes.slice().sort(function (a, b) { return a.t - b.t; }); let prev = o.from, value = o.from, velocity = 0; for (const c of changes) { if (t < c.t) break; const omega = c.omega != null ? c.omega : o.omega; const zeta = c.zeta != null ? c.zeta : o.zeta; const r = response(t - c.t, prev - c.to, 0, omega, zeta); value += (c.to - prev) + r.e; velocity += r.v; prev = c.to; } return { value: value, velocity: velocity }; }

Every project page honours the same contract, which the renderer checks: window.ready, window.STAGE, a pure window.seek(t), window.inspect(t) for the cursor seam check, and window.SFX for sounds (rules, template).

--preview renders at half size with one subframe. --from and --to are seconds and render a section. --serve prints a URL: open it with ?play and click to watch with audio.

06 Syncing
06 Check the beat grid by ear and mark moments SYNC ▶

Only a person can hear whether the beat grid sits on the music. Claude cannot, so it never says the sync is right. After analyze_song.py has written song.json, and before the brief and the tables, open the sync page to check the grid and mark the moments the tables should hit.

node $S/sync.mjs ~/promo # prints the URL and opens the browser; keeps running node $S/sync.mjs ~/promo --song ~/song.flac # once, if the song has moved or the project has no .source.json

The project's own animation plays on the left, driven by the audio clock, next to a zoomed waveform with bar and beat lines and orange marker flags; under it are the whole loop as a strip, the markers list, the buttons (Play, Clicks, Sounds right, Save) and a status line.

Key or actionDoes
← / →Scrub the playhead 10 ms; with Shift a quarter beat, with Alt to the previous or next beat line. Stopped, each step plays a short blip of the song there
HomePlayhead to the loop start
↑ / ↓Nudge the grid 5 ms later or earlier; with Shift, 20 ms

Click a flagSelect the marker and write a note in its "add a note" field (at most 200 characters, for people only, never used for timing)
NFocus the selected marker's note field
DeleteRemove the selected marker (Backspace or right-clicking its flag does the same)
CClicks on or off (the downbeat click is higher)
Ctrl+S or Cmd+SSave

Save writes the sync section of song.json (nudge_ms, bpm, meter, swing, markers, checked_by_ear) and keeps the old file as song.json.bak. It then re-runs analyze_song.py on the original song (its path is in the local, git-ignored .source.json) with the same loop window, which rebuilds song.json and re-cuts clip.wav, and the page reloads. If anything fails, the previous song.json is put back. Sounds right records today's date as checked_by_ear; a nudge, tempo or meter change clears it. While it is absent and the BPM confidence is under 0.5, check_brief.mjs warns that the grid has not been checked by ear.

A states() or cursor() row can sit on a marker by name, with an optional offset in beats. Put the action on the marker and its result after it:

{ at: 'snare', target: 'row:0', press: true } // cursor(): the press lands on the snare { at: 'snare', offset: 1, use: 'toast', text: 'Report exported' } // states(): its result, one beat later

Demo 4: Jack played Tints with the clicks over it, left the nudge at 0 because the detected grid sounded right, and pressed Sounds right (checked by ear 2026-10-01), which cleared check_brief.mjs's low confidence warning (0.39). He marked snare at 1:00.02 in the song (beat 23 of the loop) with the note "export report button should be pressed". The command bar's Export report press moved from beat 23.5 onto the snare and the toast follows one beat later. His verdict on the re-render: "genuinely perfect" (demo 4 README).

Docs. The full guide (every key, the status line, errors and known limits) is the Sync section of SKILL.md.

07 Components
07 Build from the library instead of custom code LIBRARY ▶

The kit ships 28 components in four groups: controls, feedback, data and content, and app chrome. Each one is a state the one shape morphs into, with its own motion and hotspots already built (and sounds where a component has them, such as key taps while typing): button, toggle, tabs, slider, toast, line chart, calendar, command bar, player and so on. A states() row names a component with use: and passes its props as keys. A cursor() row aims at one of its hotspots with target:. No custom layers, CSS or drawing code. The example below (an excerpt of the Onboarding recipe in RECIPES.md; the full recipe passes check_brief.mjs):

const states = () => [ { at: 0, use: 'button', label: 'Create account' }, { at: 7, use: 'toggle', on: false, label: 'Notifications' }, { at: 10, use: 'toggle', on: true, label: 'Notifications' }, // continuation: same toggle, now on { at: 18, use: 'toast', text: 'Welcome, Sam', action: 'Later' }, ]; const cursor = () => [ { at: 2, target: 'button', press: true }, { at: 8, target: 'knob', press: true }, // the press flips it { at: 20, target: 'action', press: true }, ];

Continuations. Two consecutive rows of the same component are one component changing, not a cut. The second row starts from where the first left off and animates the difference: tabs sliding from Day to Month, a progress bar filling in steps, a line chart morphing to new points. After a press, write the pressed result into the next row (a toggle pressed on is written on: true).

The planner (motion-design) now works from the library:

  1. Route. Says which path the request takes: a looping promo, a launch video, in-app motion (handed to motion-ui) or a re-time.
  2. Ask. One question per message: goal, size and length, product, song, then 3 to 6 moments with one component proposed for each.
  3. Assess. Runs the doctor, scaffolds and measures the song, turns seconds into bars, checks the theme and the state budget.
  4. Brief. Writes MOTION-BRIEF.md with real use: and target: tables, and runs check_brief.mjs until it passes.
  5. Approval gate. Stops. Nothing is built until you approve; then motion-video pastes the tables into index.html.

Demo 4 keeps the Tints audio too, for viewing here only. Re-time it to a licensed track before posting it anywhere else.

Docs. CATALOG.md lists every component with its props, hotspots, motion and an example row. RECIPES.md has five complete sequences (onboarding, checkout and more) that pass check_brief.mjs as written. WRITING-A-COMPONENT.md covers adding a new one.

08 Ready-to-post files for every destination EXPORT ▶

Each shape is rendered natively once (60 fps, 4 subframes), so a vertical Reel is laid out for 1080x1920 rather than cropped or letterboxed from the square. A file over its preset's size cap is re-encoded two-pass, then stepped down in resolution if it has to be. Every file with audio aims at -14 LUFS and a -1 dBTP true peak. check_brief.mjs checks the brief against the Reels, TikTok and Shorts safe zones (captions and buttons), and --guides renders a preview with those zones shaded. Platform limits and their sources are in presets.json; the full guide is the Export section of SKILL.md.

09 Any project
09 Re-theme and re-size to fit the project THEME ▶

extract_theme.py reads the first :root block of a stylesheet (the light theme) plus the body or html font-family, and writes theme.css and theme.json into the project. Colours are normalised to #rrggbb so springs can interpolate them. Without a CSS file it writes the house theme: warm gray, black and white, Geist.

RoleFound from these variables
canvas--bg, --background, --canvas, --color-bg, --bg-color, --page
surface--panel, --surface, --card, --paper, --bg-elevated, --color-surface
ink--ink, --text, --fg, --foreground, --color-text, --text-color
muted--muted, --text-muted, --subtle, --color-muted
accent--accent, --primary, --brand, --color-primary, --color-accent
font--font, --font-sans, --font-family, --font-body, or the body font
pos, neg (optional)Success and danger colours, included only when the CSS defines them

When a role is picked wrongly, override it and check the printed theme:

python3 $S/extract_theme.py app/style.css --out ~/promo --map accent=--brand

Pages then use the roles (canvas surface ink muted accent) or var(--accent), never a hex value, so the piece re-themes with the project. Use var(--pos) and var(--neg) only when the theme has them.

Sizes. --size square is 1440x1440 (the default), vertical is 1080x1920 for Reels, TikTok and Shorts, landscape is 1920x1080, or pass WxH with even numbers of at least 64.

Long pieces and 4K. There is no hard limit: --bars 28 is about a minute at 109 BPM and --size 3840x2160 is 4K. Above roughly 1440 px, scale the camera zoom and the cursor by K = min(W, H) / 1440 so the design keeps its proportions and renders sharper, not smaller (exact lines). Full quality 4K renders at about 19 seconds per second of video on an Apple M5, so a minute takes 20 to 30 minutes: time a 5 second section with --from 0 --to 5 first, iterate with --preview, and plan a minute as 3 or 4 chapters.

10 Song rules
10 What song.json tells you RULES ▶
  • Comfort band. 100 to 130 BPM. Outside it the analysis warns: below, keep one event per beat; above, consider half-time events or half-beat accents. Say the BPM and any warning out loud before planning.
  • House spring. rules.spring sets zeta 0.85 and a settle of 0.6 beat (0.33 s at 109 BPM). The template already uses it. Camera and cursor use zeta 1.
  • Hold time. rules.min_hold_beats is the fewest beats a state may hold, from one second of screen time (2 beats at 109 BPM). rules.max_states follows from it (14 for a 7-bar loop).
  • Cue placement. Every sound sits on its beat's measured cue_t, not the grid time. Presses use sfx/click.wav, typing uses sfx/key.wav, anything else goes through extraSfx(). Put the biggest changes on the strongest per-beat accent values.
  • Loop start. Choose --start-bar at a section boundary inside a strong section, and use a different bar for each piece made from one song. Demo 1 starts at bar 21, demo 2 at bar 7.
  • Licence. A commercial track is for local viewing. Ask for a file and never download music.
11 In-app motion
11 The project's motion spec wins MOTION-UI ▶

Before proposing anything, motion-ui looks for the project's motion rules and treats them as the spec: docs folders named motion, animation or handoff, CSS tokens such as --t-*, --dur-* and --ease-*, and existing transition:, @keyframes and reduced-motion handling. If the spec bans bounce, every spring is zeta 1, and durations come from the tokens through Springs.fromSettle(tokenSeconds, zeta).

The worked example is demo 3. The dock indicator used to slide on a CSS transform transition. It now rides two edges, each on its own critically damped spring (zeta 1). The edge on the side it is heading toward settles in 0.7 of --t-travel (220 ms) and the trailing edge takes the full time, so the pill reaches ahead and gathers up behind. Each edge keeps its position and velocity between navigations and is held between where it was and where it is going, so a quick reversal cannot pass its target. Reduced motion and a missing requestAnimationFrame make the pill jump.

// motion-ui pattern 2, generic form of the dock pill: skills/motion-ui/references/patterns.md at 8247624 function indicatorEdges(from, changes, t, settle, n, lead = 0.7) { const trail = Springs.fromSettle(settle, 1), fast = Springs.fromSettle(settle * lead, 1); const hold = (x, a, b) => Math.min(Math.max(x, Math.min(a, b)), Math.max(a, b));

Full pattern and its tests: patterns.md, patterns.test.mjs.

The branch motion-demo in the finance app is unmerged and unpushed, and main is untouched. Its tests pin the behaviour: settles on target, never overshoots, retargets stay continuous, and the pill never collapses or leaves the dock.

SymptomCause and fix
