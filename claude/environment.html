01 The dash hook
01 A PreToolUse guard that blocks the write outright HOOK ▶

A PreToolUse hook runs before a tool call and can refuse it. This one matches Write and Edit, and exiting with status 2 blocks the call and hands the message back as feedback. Preference lives in a memory file; this is the part that actually stops the write.

"hooks": { "PreToolUse": [ { "matcher": "Write|Edit", "hooks": [ { "type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/no-em-dash.py\"" } ] } ] }

Four decisions in it are worth knowing, because each one is the difference between a guard that helps and a guard that gets switched off:

DecisionReason
Scans only the incoming text (content or new_string), never the target fileA file that already contains a stray dash stays editable. Otherwise one old page would wedge every unrelated edit to it.
Catches both characters and their entity spellings (&mdash;, &#8212;, &#x2014;)HTML makes it trivially easy to smuggle the same character past a naive check.
Escape hatch: allow-dash anywhere on the line skips itOccasionally a dash is genuinely required, and a guard with no exit is a guard that gets removed.
Fails open. Any internal error exits 0 and permits the writeA punctuation guard that can block all file edits is worse than the punctuation.

It is scoped to paths under ~/Documents/AUTOMATION, so it covers the wiki and everything beside it. It covers files only. A commit message goes nowhere near it, so dashes there stay a matter of attention.

The rejection message names the file and line, then tells you to recast the sentence rather than swap in a hyphen, on the grounds that a sentence reaching for a dash usually wants rewording.

The hook in full, snapshot of ~/Documents/AUTOMATION/.claude/hooks/no-em-dash.py. The dash characters are written as chr() escapes on purpose, so the file does not trip its own rule when edited.

#!/usr/bin/env python3 """PreToolUse guard: keep em dashes and en dashes out of Jack's repos. Blocks Write/Edit calls whose *new* content carries a dash character or its HTML entity form. Only the incoming text is scanned, never the target file, so a runbook that already contains a stray dash stays editable. Escape hatch: put "allow-dash" anywhere on the line (in a comment) and that line is skipped. Fails open. Any internal error exits 0 and permits the write, because a punctuation guard that can block all file edits is worse than the punctuation. The dash characters below are written as escapes on purpose, so this file does not trip its own rule when edited. """ import json import os import re import sys GUARDED_ROOT = "/Users/jackwade/Documents/AUTOMATION" ESCAPE_MARKER = "allow-dash" MAX_REPORTED = 5 # Literal characters, kept as escapes so this source stays self-compatible. CHARS = { chr(0x2014): "em dash (U+2014)", chr(0x2013): "en dash (U+2013)", } # Entity spellings of the same two characters. ENTITIES = re.compile( r"&(?:mdash|ndash|#8212|#8211|#x2014|#x2013);", re.IGNORECASE, ) # Which field carries the text being introduced. CONTENT_FIELD = { "Write": "content", "Edit": "new_string", } def under_guarded_root(path): if not path: return False resolved = os.path.realpath(path) root = os.path.realpath(GUARDED_ROOT) return resolved == root or resolved.startswith(root + os.sep) def violations(text): """Yield (line_number, description, line) for each offending line.""" for lineno, line in enumerate(text.splitlines(), start=1): if ESCAPE_MARKER in line: continue for char, description in CHARS.items(): if char in line: yield lineno, description, line break else: match = ENTITIES.search(line) if match: yield lineno, "HTML entity %s" % match.group(0), line def main(): payload = json.load(sys.stdin) field = CONTENT_FIELD.get(payload.get("tool_name")) if field is None: return 0 tool_input = payload.get("tool_input") or {} if not under_guarded_root(tool_input.get("file_path")): return 0 text = tool_input.get(field) if not isinstance(text, str): return 0 found = list(violations(text)) if not found: return 0 name = os.path.basename(tool_input.get("file_path", "?")) report = ["BLOCKED: dash characters are not allowed in this repo."] for lineno, description, line in found[:MAX_REPORTED]: report.append(" %s line %d: %s" % (name, lineno, description)) report.append(" %s" % line.strip()[:120]) if len(found) > MAX_REPORTED: report.append(" ... and %d more" % (len(found) - MAX_REPORTED)) report.append("") report.append("Recast the sentence with a comma, colon, or parentheses.") report.append("Do not just swap in a hyphen; the phrasing usually wants rework.") report.append('If the dash is genuinely required, add "%s" to that line.' % ESCAPE_MARKER) sys.stderr.write("\n".join(report) + "\n") return 2 if __name__ == "__main__": try: sys.exit(main()) except Exception: sys.exit(0)
02 The permission model
02 Broad allow list, prompt only for real damage PERMISSIONS ▶

The allow list in .claude/settings.local.json is deliberately broad. A permission prompt on every git status trains you to approve without reading, which costs more safety than it buys. The prompts are reserved for operations that could actually lose work.

Allowed without promptingCovers
File and process basicscd, cp, mv, mkdir, rm, touch, chmod, kill, pkill, open, osascript
The actual workgit, gh, python3, node, curl, ./serve.sh
Reads outside the project~/.cache, ~/Downloads, /opt/homebrew/bin, /tmp
Network and GitHubWebSearch, fetches from github.com and ibm.com, and the GitHub MCP calls for PRs and commits

The deny list is the guardrail, and it is not a sandbox. It stops the specific commands that destroy work irrecoverably or execute something unreviewed. It is not an attempt to contain a determined process, and treating it as one would be a mistake.

"deny": [ "Bash(sudo *)", "Bash(rm -rf *)", "Bash(rm -fr *)", "Bash(rm -r *)", "Bash(git push --force *)", "Bash(git push -f *)", "Bash(git reset --hard *)", "Bash(git clean -fd *)", "Bash(curl * | sh)", "Bash(curl * | bash)" ]

The pattern behind the list: recursive deletion, history rewriting, and piping a download straight into a shell. Everything on it either cannot be undone or runs code nobody read.

The allow list also accumulates entries automatically as prompts get approved, and some are one off noise from a single session (a scratchpad path, a fragment of a grep). Worth pruning occasionally so the file stays readable. /fewer-permission-prompts is the tool for looking at it.

03 The GitHub token
03 Passed through a helper, never printed SECRET ▶

The token lives in ~/.claude/settings.json as env.GITHUB_PERSONAL_ACCESS_TOKEN and stays there. The git remote deliberately carries no token in its URL, and the osxkeychain entry was cleared, so a plain push fails with could not read Username for 'https://github.com'. That failure is the design working, not a fault.

git -c credential.helper='!f(){ echo username=triippiing; echo "password=$GITHUB_PERSONAL_ACCESS_TOKEN"; };f' push origin main

Never echo, print, or interpolate that variable anywhere its value would be displayed. It lands in the session transcript if you do, and the transcript then needs scrubbing. Reference it only inside the helper above, where the shell expands it without it ever being rendered.

Keeping it out of the remote URL matters for the same reason: a URL with a token in it shows up in git remote -v, in .git/config, and in the output of half the commands anyone might run while screen sharing.

04 What is not installed here
04 Four absences, and what to use instead GOTCHA ▶

Each of these has already been assumed present and cost time. gh is on the permission allow list, which makes the absence more confusing rather than less: permitted is not the same as installed.

MissingInstead
ghQuery the Actions API with curl and a bearer token. gh run watch is not available.
node, deno, bunNothing on PATH runs JavaScript. Anything scripted here is Python 3.
jscTo syntax check chrome.js, use osascript with new Function(src).
Cached git credentialsThe inline credential helper above. See phase 03.
# syntax check chrome.js without a JS runtime on PATH osascript -l JavaScript -e 'new Function(ObjC.unwrap($.NSString.stringWithContentsOfFileEncodingError("assets/js/chrome.js", $.NSUTF8StringEncoding, null)))' \ && echo "parsed OK"

The wiki itself is built to survive this: build_index.py is pure Python stdlib and serve.sh wraps python3 -m http.server, so the whole toolchain is macOS default Python and a browser. No dependency here is an accident.

05 Two things that will fool you
05 Unstyled pages and stale JavaScript PREVIEW ▶

Never open a runbook from Finder. Under file:// the browser blocks the shared stylesheets in assets/css/, because they sit in a parent directory. The page renders completely unstyled and you will report a working change as broken.

./serve.sh # python3 -m http.server on :8765 open http://localhost:8765/

assets/js/chrome.js caches hard. It is a stable URL that keeps gaining behaviour, so Safari will happily serve a cached copy and you will conclude a change is broken when it is not. Check in a private window, use Cmd+Option+R to reload from origin, or add a cache busting query string.

This is what /wiki-check exists for. It requests every shared asset over http and reports the status codes, which is the only way to prove the assets resolve. A visual check cannot distinguish a broken stylesheet from a broken page.

⚠ Key Notes
  • None of this config is version controlled. This page is the only record, and it is a hand copy taken on the date in the identity strip.
  • The dash hook fails open on purpose. If it ever seems to have stopped working, that is the designed behaviour on error, not a silent pass.
  • The deny list is a guardrail against irrecoverable commands, not a sandbox. Do not reason about it as containment.
  • The token is referenced only inside the credential helper. Printing it contaminates the transcript.
  • gh is allowed by the permission list and absent from the machine. Permitted is not installed.
  • Serve over http and verify in a private window before believing anything about how a page looks.
